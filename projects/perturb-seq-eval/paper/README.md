# Paper — Does Multi-Agent Confidence Predict Task Difficulty, or Only React to It? A Pre-registered Test on Perturb-seq

This directory holds the manuscript. The paper tests, under five pre-registered hypotheses,
whether the confidences stated by a group of large-language-model agents indicate how hard a
task is; the tasks are predictions of gene-expression responses in Perturb-seq data (pooled
CRISPR screens read out by single-cell RNA sequencing). The longer argument is in
[`../docs/THESIS.md`](../docs/THESIS.md), and the hypotheses, criteria and amendments are in
[`PREREGISTRATION.md`](PREREGISTRATION.md).

**Status:** the manuscript is filled from the v0.6.0 sweep (run `20260929T035447Z-ce5f237`).
Every result value is a `\res...` macro in `sections/generated_numbers.tex`, generated by
`scripts/paper/fill_v060_numbers.py` from `artifacts/v0.6.0/` (the tests run it with `--check`);
no number is typed by hand. The exploratory values, which were added after the outcome under
the sixth amendment to the pre-registration, are `\expl...` macros in
`sections/generated_exploratory.tex`, generated with
`data/exploratory_v060.json` by `scripts/paper/fill_v060_exploratory.py` (also run with
`--check` in the tests); the two figures are drawn from that JSON by
`scripts/paper/make_v060_figures.py`.
All values of the earlier release v0.5.0 are
superseded: the appendix "Corrections relative to v0.5.0"
(`sections/corrections.tex`) maps each one to the defects that supersede it.

**How to cite:** see [`../CITATION.cff`](../CITATION.cff) and the concept DOI
<https://doi.org/10.5281/zenodo.19716140>.

## Pipeline that will produce the results

```bash
cd projects/perturb-seq-eval

# 1. The sweep: preflight + trainer sweep + lifecycle sweep in one process.
#    ANTHROPIC_API_KEY is injected by Infisical (never written to disk; where
#    it is stored is not recorded, RR-1); preflight refuses the whole run
#    without it, and requires paper/PREREGISTRATION.md committed with no
#    local edits (the pinned pre-registration).
infisical run \
    --projectId <INFISICAL_PROJECT_ID> --env <ENV> -- \
    modal run scripts/modal/app_v05.py::entrypoint --version v0.6.0 \
    --norman-n-singletons 15 --norman-n-doublets 5 --seeds 3 --prior-spend-usd 1.3548

# Modal client: the recorded run launched with modal 1.5.5, the client in its provenance
# (artifacts/v0.6.0/provenance.json lib_versions.modal); for v0.6.0 the entrypoint refuses any
# other client. poetry.lock (modal 1.4.2, last regenerated at v0.3.0) has drifted and is not
# the authority for this release; a fresh resolve gives a newer modal.
# If the check refuses your client (a fresh venv resolves a newer modal), install exactly the
# recorded client named above (pip install "modal==<that version>") before re-running.
# Known gap (declared, fixed after the deposit): the pre-registered version is held twice,
# v05_sweep.PREREGISTERED_VERSION and v05_preflight.PREREGISTERED_VERSIONS; they agree as of
# this commit, and neither is authoritative over the other.
# Known gap (declared): two published releases are not documented here. The CHANGELOG stops at
# 0.5.0 while Zenodo v0.5.1 (10.5281/zenodo.20060974) and v0.5.2 (10.5281/zenodo.20074427) are
# public (see CHANGELOG). v0.5.2's record has empty notes and repeats the v0.5.0 abstract; by
# md5 comparison only its paper.pdf differs from v0.5.1 (identical to Figshare 32086920 v5's).
# What changed inside the PDF is not recorded.
# Declared (2026-10-16): on Figshare the author comes from the depositing account's profile
# (Figshare adds the owner automatically; the script sends no authors), so this repository cannot
# set it; a publish run checks it against publish.yml expected_author and refuses otherwise. The
# venues show different name forms ON PURPOSE: Zenodo "Mo, Mang-yin" (Family, Given, from
# publish.yml) and Figshare "Mang-yin Mo" (the profile name, once the profile is renamed).
# Do not "fix" one to match the other, and do not re-add authors to the Figshare payload: that
# lists the author twice.
# 2. Analyse the downloaded run files -> artifacts/v0.6.0/summary.json
# Bit-exact on Python 3.12: float sum() is compensated from 3.12, so on 3.10/3.11 the
# backbone entropy (five summary.json keys) differs by one ulp; the run itself ran on 3.11.0.
python -m perturb_eval.experiments.e_v05_real_traces artifacts/v0.6.0
```

`scripts/paper/fill_v060_numbers.py` writes `sections/generated_numbers.tex` from
`summary.json`, `provenance.json`, `lifecycle_runs.jsonl` and
`data/projection_v060.json`; `--check` fails if the committed file is stale
(`tests/test_fill_v060_numbers.py`). `scripts/paper/fill_v060_exploratory.py` writes
`data/exploratory_v060.json` and `sections/generated_exploratory.tex` from the same run
files, after reproducing the committed pre-registered `1 − ΔC` correlations
(`tests/test_fill_v060_exploratory.py`); `scripts/paper/make_v060_figures.py` draws
`figures/fig_h4_scatter.pdf` and `figures/fig_confidence_by_round.pdf` from that JSON and
is re-run only when the plotted values change. `scripts/paper/fill_v050_numbers.py` fills
`sections/v050_results.tex`, which `paper.tex` no longer inputs. Build products
(`paper.pdf`, `.aux`, `.log`, `.out`, `.bbl`, `.blg`) are not tracked; rebuild with
`latexmk` from the sources.
