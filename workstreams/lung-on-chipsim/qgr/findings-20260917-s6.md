## reviewer-security — measured matrix; ONE HIGH blocks release

  Fix: scan the footer too (pq.read_schema -> schema.metadata + every field.metadata), or scan the

S6-03 [MED] A declared path is a permanent, CONTENT-BLIND exemption: no digest pin, no existence

  (declare data/compounds.h5ad today, commit the record-carrying file tomorrow — nothing ever
  reddens); and every declared file is a BUILD OUTPUT, so regenerating the paper or re-exporting
  the AnnData with drug annotations leaves the guard silent forever, because the declaration keys
  on the PATH, not the bytes just verified. Fix: path -> sha256, plus the existence test the ledger
  sets already have.
S6-04 [MED] REGRESSION I INTRODUCED: a PLAIN-TEXT file named `*.parquet` was scanned before and is
  not now — read_parquet raises, `except Exception` returns None, the accession is never looked
  for. Not silent (it reddens the undecodable test) but the DIAGNOSIS is wrong, and following it
  ("declare it") converts a live content violation into a permanent exemption. Realistic trigger:
  git-lfs, where every tracked *.parquet is a ~130-byte UTF-8 pointer file.
  Fix: fall through to read_text before returning None.
S6-05 [MED] EXPANSION BOMB, measured: a 30 KiB dictionary-encoded parquet expands to 186.9 MiB of
  scan string (6,317x), peak RSS 592 MiB; a 5 MB committed parquet extrapolates to ~30 GB. Both
  callers call `_scannable_text` independently, so every tracked parquet is parsed and stringified
  TWICE per run. MemoryError subclasses Exception, so an OOM inside read_parquet is swallowed and

  verdict, and the pressure when CI is red is to declare — the same false-clean in a new costume.
  Fix: bound the read (num_rows / serialized_size), stream row groups, cache per path, and handle
  MemoryError separately from Exception.
